# Отчёт по семестровому заданию №3

**Тема:** Сравнительное исследование алгоритмов хэширования и производительности
подбора паролей (MD5, SHA-1, bcrypt, Argon2).

**Цель:** оценить сложность и время восстановления пароля методом полного перебора
для старых (MD5, SHA-1) и современных (bcrypt, Argon2) алгоритмов хэширования;
сравнить собственный переборщик с профессиональным инструментом; сделать выводы о
влиянии сложности пароля и выбранного алгоритма на стойкость.

---

## 1. Методика

1. Реализован собственный многопоточный переборщик на Java (см. исходный код в
   `src/main/java/ru/mirea/bruteforce`).
2. Перебор ведётся по заданному алфавиту для длин от `min` до `max`. Пространство
   кандидатов длины L нумеруется числами `0 .. base^L-1` и делится на равные
   диапазоны между потоками.
3. Проверка кандидата:
   - **MD5 / SHA-1** — вычисление хэша (`MessageDigest`) и сравнение hex-строк;
   - **bcrypt** — `BCrypt.checkpw` (соль и cost берутся из самого хэша);
   - **Argon2** — `argon2.verify` (параметры и соль — из строки хэша).
4. Время измеряется `System.nanoTime()`; фиксируются число проверенных кандидатов
   и скорость (хэшей/с).
5. Те же хэши проверяются профессиональным инструментом (hashcat / John the Ripper),
   время сравнивается.

## 3. Сравнение с профессиональным инструментом

### hashcat

Режимы (`-m`): MD5 — `0`, SHA-1 — `100`, bcrypt — `3200`, Argon2 — на момент
написания hashcat Argon2 нативно не поддерживает (использовать John the Ripper).

```bash
# Подготовка: по одному хэшу в файл
echo "e10adc3949ba59abbe56e057f20f883e" > md5.hash

# Перебор по цифрам, маска до 8 знаков
hashcat -m 0   -a 3 md5.hash  ?d?d?d?d?d?d?d?d
hashcat -m 100 -a 3 sha1.hash ?d?d?d?d?d?d?d?d
hashcat -m 3200 -a 3 bcrypt.hash ?l?l?l?l        # bcrypt, строчные буквы
```

### John the Ripper

```bash
# john распознаёт формат по строке хэша
john --format=raw-md5   --incremental md5.hash
john --format=raw-sha1  --incremental sha1.hash
john --format=bcrypt    --incremental bcrypt.hash
john --format=argon2    --incremental argon2.hash   # поддержка Argon2 есть в John
john --show md5.hash                                 # показать найденное
```

## 4. Выводы

1. **Сложность пароля** влияет экспоненциально: каждый дополнительный символ
   умножает пространство перебора на мощность алфавита. Переход с цифр (10) на
   `alphanum` (62) увеличивает число вариантов фиксированной длины в десятки раз.
2. **Выбор алгоритма** влияет ещё сильнее: MD5 и SHA-1 вычисляются миллионами в
   секунду, поэтому короткие и словарные пароли вскрываются мгновенно — такие хэши
   **нельзя** использовать для хранения паролей.
3. **bcrypt** за счёт настраиваемого cost-фактора замедляет перебор в десятки тысяч
   раз. Увеличение cost на 1 удваивает время проверки — защита масштабируется вместе
   с ростом мощности оборудования.
4. **Argon2id** дополнительно memory-hard (требует десятки МБ на проверку), что
   обесценивает GPU/ASIC-ускорение и делает его наиболее стойким из четырёх.
5. **Многопоточность** даёт практически линейное ускорение собственного инструмента
   (×(число ядер)), но не меняет вывода: против адаптивных функций полный перебор
   на CPU непрактичен уже для паролей средней сложности.

**Практическая рекомендация:** для хранения паролей использовать Argon2id (или
bcrypt/scrypt) с солью и адекватными параметрами стоимости; MD5 и SHA-1 для этой
задачи непригодны.
