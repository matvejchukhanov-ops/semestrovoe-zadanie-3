# Отчёт по семестровому заданию №3

**Тема:** Сравнительное исследование алгоритмов хэширования и производительности
подбора паролей (MD5, SHA-1, bcrypt, Argon2).

**Цель:** оценить сложность и время восстановления пароля методом полного перебора
для старых (MD5, SHA-1) и современных (bcrypt, Argon2) алгоритмов хэширования;
сравнить собственный переборщик с профессиональным инструментом; сделать выводы о
влиянии сложности пароля и выбранного алгоритма на стойкость.

---

## 1. Методика

1. Реализован собственный многопоточный переборщик на Java (см. исходный код в
   `src/main/java/ru/mirea/bruteforce`).
2. Перебор ведётся по заданному алфавиту для длин от `min` до `max`. Пространство
   кандидатов длины L нумеруется числами `0 .. base^L-1` и делится на равные
   диапазоны между потоками.
3. Проверка кандидата:
   - **MD5 / SHA-1** — вычисление хэша (`MessageDigest`) и сравнение hex-строк;
   - **bcrypt** — `BCrypt.checkpw` (соль и cost берутся из самого хэша);
   - **Argon2** — `argon2.verify` (параметры и соль — из строки хэша).
4. Время измеряется `System.nanoTime()`; фиксируются число проверенных кандидатов
   и скорость (хэшей/с).
5. Те же хэши проверяются профессиональным инструментом (hashcat / John the Ripper),
   время сравнивается.

## 2. Результаты собственного инструмента

### 2.1 Проверочные замеры (подбор по известному паролю)

| Алгоритм | Пароль | Алфавит | Проверено | Время, с | Скорость, хэш/с |
|----------|--------|---------|-----------|----------|-----------------|
| MD5      | `123456` | digits (≤8) | 1 080 535 | 0.300 | ~3 600 000 |
| SHA-1    | `123456` | digits (≤8) | 1 096 991 | 0.335 | ~3 275 000 |
| bcrypt   | `ab`     | lower (≤2)  | 619       | 7.635 | ~81 |
| Argon2id | `a`      | lower (≤1)  | 20        | 1.011 | ~20 |

**Наблюдение:** при одинаковом подходе bcrypt медленнее MD5 примерно в **44 000 раз**
(81 против 3,6 млн хэшей/с), Argon2 — ещё медленнее и дополнительно требует 64 МБ
памяти на каждую проверку.

### 2.2 Тестовые хэши ТЗ

Сводная таблица по образцу из задания (время в секундах; «—» — не вскрыт за
отведённый бюджет):

Восстановлены **все четыре пароля** (совпадают для всех алгоритмов):

| Сложность | Пароль | Чем восстановлен |
|-----------|--------|------------------|
| лёгкий    | `123456` | свой инструмент / John / hashcat |
| средний   | `apple`  | словарь (rockyou/John) |
| сложный   | `pow12`  | hashcat, rockyou + правила best66 |
| очень сложный | `Create` | hashcat, rockyou + правила best66 |

> «Сложный» (`pow12`) и «очень сложный» (`Create`) полным перебором по алфавиту не
> берутся за разумное время, но **оба есть в словаре rockyou** (14 млн паролей),
> поэтому вскрываются словарной атакой с правилами (best66) за секунды на GPU для
> MD5/SHA-1. Поскольку пароли во всех алгоритмах одни и те же, найденные из быстрых
> хэшей слова подставлены кандидатами к bcrypt/Argon2 — там они подтвердились
> мгновенно (прямой перебор rockyou по bcrypt/Argon2 занял бы часы).
>
> **Вывод:** стойкость даёт не длина пароля, а его случайность. `pow12`/`Create`
> выглядят «сложными», но, попав в словарь, ломаются. bcrypt/Argon2 не спасают
> слабый пароль — они лишь кратно увеличивают время атаки.

## 3. Сравнение с профессиональным инструментом

Использованы два эталона: **John the Ripper 1.9.0-jumbo-1** (CPU, OMP, AVX2) для
MD5/SHA-1/bcrypt и **hashcat 8.0.0** (GPU, NVIDIA RTX 3050, OpenCL) для argon2id.
Файлы хэшей ТЗ по алгоритмам: `md5.txt`, `sha1.txt`, `bcrypt.txt`, `argon2.txt`
(по 4 вектора).

```bash
# Перебор по маске из цифр (как в своём инструменте на лёгком пароле)
john --format=raw-md5  --mask='?d?d?d?d?d?d' md5.txt
john --format=raw-sha1 --mask='?d?d?d?d?d?d' sha1.txt

# Словарь со встроенными правилами — берёт типовые пароли (apple, 123456, ...)
john --format=raw-md5  --wordlist --rules md5.txt
john --format=raw-sha1 --wordlist --rules sha1.txt
john --format=bcrypt   --wordlist --rules bcrypt.txt

# Показать восстановленные пароли
john --format=raw-md5  --show md5.txt
```

argon2id у John 1.9.0-jumbo-1 не поддерживается (эта сборка реализует только
**argon2d/argon2i**, хэши ТЗ — argon2id → «No password hashes loaded»). Поэтому для
argon2id взят **hashcat 8.0.0** на GPU:

```bash
# Все 4 argon2-хэша ТЗ имеют одну соль (saltsalt), а плагин argon2 не грузит
# несколько хэшей с одинаковой солью — поэтому по одному хэшу на запуск.
hashcat -m 34000 -a 0 -d 1 a2/h1.txt wordlist.txt   # argon2id, словарь
hashcat -m 34000 --show a2/h1.txt                    # показать результат
hashcat -m 34000 -b -d 1                             # бенчмарк скорости
```

**Фактические замеры (один стенд):**

| Алгоритм | Свой инструмент (CPU) | Эталон | Эталон быстрее | Взломано эталоном |
|----------|------------------------|--------|----------------|-------------------|
| MD5      | ~3 000 000 к/с | John ~29 400 000 к/с (маска) | ~10× | 123456, apple |
| SHA-1    | ~3 300 000 к/с | John ~15 400 000 к/с (маска) | ~5× | 123456, apple |
| bcrypt   | ~75–81 к/с | John ~354 к/с (16 потоков OMP) | ~4–5× | 123456, apple |
| Argon2id | ~20 к/с (m=64 МБ) | hashcat ~199 H/s (GPU RTX 3050, m=65536,t=3) | ~10× | 123456, apple |

Профессиональные утилиты быстрее за счёт оптимизированных ядер (SIMD/ассемблер),
многопоточности, правил перебора и GPU, но **относительная** разница между
алгоритмами сохраняется: быстрые хэши (MD5/SHA-1 — десятки миллионов в секунду)
уступают адаптивным (bcrypt/Argon2 — сотни в секунду) на 4–5 порядков независимо от
инструмента. Даже на GPU argon2id даёт лишь ~199 H/s — перебор сложных паролей
остаётся непрактичным.

## 4. Выводы

1. **Сложность пароля** влияет экспоненциально: каждый дополнительный символ
   умножает пространство перебора на мощность алфавита. Переход с цифр (10) на
   `alphanum` (62) увеличивает число вариантов фиксированной длины в десятки раз.
2. **Выбор алгоритма** влияет ещё сильнее: MD5 и SHA-1 вычисляются миллионами в
   секунду, поэтому короткие и словарные пароли вскрываются мгновенно — такие хэши
   **нельзя** использовать для хранения паролей.
3. **bcrypt** за счёт настраиваемого cost-фактора замедляет перебор в десятки тысяч
   раз. Увеличение cost на 1 удваивает время проверки — защита масштабируется вместе
   с ростом мощности оборудования.
4. **Argon2id** дополнительно memory-hard (требует десятки МБ на проверку), что
   обесценивает GPU/ASIC-ускорение и делает его наиболее стойким из четырёх.
5. **Многопоточность** даёт практически линейное ускорение собственного инструмента
   (×(число ядер)), но не меняет вывода: против адаптивных функций полный перебор
   на CPU непрактичен уже для паролей средней сложности.

**Практическая рекомендация:** для хранения паролей использовать Argon2id (или
bcrypt/scrypt) с солью и адекватными параметрами стоимости; MD5 и SHA-1 для этой
задачи непригодны.
